# v26.05 code review

## Finding

**Severity:** High for HIL qualification usability.

Robot command-line variables such as `--variable HIL_ENABLED:true` arrive as strings. The v26.04 suite passed the lowercase string directly to `Should Be True` and Robot expression evaluation, which attempted to resolve Python name `true` and failed before hardware connection. The same defect affected all conditional profile variables.

## Correction

- Added one centralized, case-insensitive Boolean normalizer.
- Normalized all external HIL Boolean variables before use.
- Unknown values fail closed with the variable name and received value.
- Updated launchers to use canonical Boolean spelling.
- Delayed coverage startup until preflight succeeds.
- Guarded finalization when preflight prevents coverage startup.

## Regression risk

Low. The production driver API and SCPI behavior are unchanged. Changes are isolated to HIL orchestration, runner arguments, version metadata, and test evidence.

## Residual risk

Official Robot parsing and physical hardware execution must be rerun in the user's uv environment because Robot Framework is unavailable in the package-build container.
