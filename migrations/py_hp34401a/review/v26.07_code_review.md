# Code Review — rf_hp34401a v26.07

**Release:** 26.07 / 26.7.0  
**Review status:** RETROSPECTIVE REVIEW — RELEASE EVIDENCE SUPERSEDED BY REMEDIATION  
**Review date:** 2026-08-16

## Scope

v26.07 added the RFDS-008 structured evidence engine and the `Export Diagnostic Bundle` public keyword, increasing the public Robot surface from 108 to 109 keywords.

## Positive findings

- evidence operations correlate keyword calls with SCPI protocol traffic;
- credential-shaped operation arguments are redacted;
- evidence files use deterministic JSON/JSONL structures and SHA-256 manifests;
- evidence can be disabled explicitly without changing instrument semantics;
- protocol, identity, environment and diagnostic bundle artifacts are separated by role;
- the change did not intentionally alter SCPI measurement sequencing.

## Findings discovered by the 2026-08-16 deep review

### V2607-REV-001 — Run status aggregation could produce a false PASS — CRITICAL

A failed keyword followed by a successful disconnect could finalize the evidence run as `PASS`, because the disconnect call supplied the final run status. The remediation now accumulates failure state inside `EvidenceRun`; any prior recorded failure forces final status `FAIL`.

### V2607-REV-002 — Diagnostic export could make the live manifest stale — HIGH

The old implementation wrote the manifest/archive and then appended a `DIAGNOSTIC_BUNDLE_EXPORTED` event. The remediation records the event before creating the manifest and archive snapshot.

### V2607-REV-003 — Listener cleanup could leave evidence unfinalized — HIGH

The old library listener closed sessions but did not finalize the evidence run if users omitted an explicit disconnect keyword. The corrected public facade performs best-effort cleanup and finalizes exactly once without masking the original Robot failure.

### V2607-REV-004 — Simulation evidence was initialized as REAL_HARDWARE — HIGH

The evidence run previously defaulted to `REAL_HARDWARE`. The remediation starts as `UNKNOWN` and changes to `SIMULATION` or `REAL_HARDWARE` only from the actual connected transport identity.

### V2607-REV-005 — Error records did not carry the public structured error code — MEDIUM

The remediation records an `error_code` field when the exception exposes the RFDS public code.

## Regression coverage added

- prior keyword failure + successful disconnect => final run `FAIL`;
- diagnostic export leaves the live evidence root hash-valid;
- simulated sessions are labeled `SIMULATION`;
- listener close finalizes successful runs;
- listener close preserves prior failure status.

## Verdict

The original v26.07 release review record was missing and the evidence implementation contained release-blocking defects. This retrospective review therefore **does not approve the historical v26.07 source as production-ready**.

The corrected `dev` implementation must pass current Python, Robot, protocol/static conformance, package-build and installed-wheel gates, followed by real HIL on the exact frozen commit before a release or D2/P1 claim is made.
