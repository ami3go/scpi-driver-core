# Code review — v26.02

## Scope

Reviewed the v26.01 HP34401A Robot adapter against the project platform API, RFDS-017 AI Driver Contract v3.0, and RFDS-018 AI Test Bench Contract v1.0.

## Findings and corrections

| Severity | Finding | Correction | Residual risk |
|---|---|---|---|
| High | No canonical AI-readable contract or staleness lock existed. | Added `ai_contract.yaml`, lock, validator, tests, and CI gate. | Schema evolution must be tracked as RFDS drafts mature. |
| Medium | Connection was exposed only through transport-specific keywords, reducing API uniformity. | Added transport-neutral `Connect DMM` and `Disconnect DMM`; retained old keywords. | Vendor VISA behavior remains backend-specific. |
| Medium | Runtime metadata and capability discovery were incomplete. | Added metadata and capability keywords. | Firmware support matrix remains based on HIL evidence. |
| Medium | Legacy multi-driver orchestrators expected `connect_to_dmm`. | Added non-Robot compatibility methods in the library. | Other undocumented third-party aliases may still require adaptation. |
| Medium | RFDS-018 bench information was absent. | Added a conservative bench template and guide. | A template is not a validated bench contract. |
| Low | Strict stable resistance used a variadic public signature. | Replaced it with an exact explicit signature. | None identified. |

## Architecture assessment

The implementation retains the correct adapter architecture. SCPI, parsing, transport, retry, overload, and instrument-state behavior remain in the core driver. The Robot layer owns framework concerns and semantic discovery. No second SCPI implementation was introduced.

## API stability

All v26.01 Robot keywords and parameter ordering are preserved. New keywords are additive. Compatibility methods are intentionally not decorated and therefore do not become accidental Robot keywords.

## Safety assessment

The driver contract explicitly states that resistance/continuity/diode modes require a de-energized DUT, current measurement requires a verified series path, and raw SCPI bypasses high-level semantic safeguards. Bench-wide interlocks and shutdown ordering remain RFDS-018 responsibilities.

## Open qualification items

- Real VISA/GPIB and RS-232 HIL on intended instrument firmware.
- Long-duration connection and repeated-measurement stability.
- Multi-process resource exclusion under the target test runner.
- Completion and approval of the actual bench `system_ai_contract.yaml`.
