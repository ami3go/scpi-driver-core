# v26.02 — RFDS-008 evidence engine and RFDS-019 hardware conformance

- Added `rf_ngi_n83624/evidence.py`: an RFDS-008 evidence engine recording
  every public keyword call (arguments, duration, result/failure) and every
  underlying SCPI write/query to a per-connection-alias, timestamped run
  directory under `results/session/rf_ngi_n83624/`, with a SHA-256 evidence
  manifest, JSONL event/operation/error streams, redaction of
  credential-shaped arguments, and correlation IDs linking nested keyword
  calls (e.g. `Close All N83624 Connections` calling `Close N83624
  Connection` once per alias). Independent of, and complementary to, the
  existing opt-in `audit_log_path` JSONL audit log.
- Added `ngi_n83624.driver.N83624CellSimulator.protocol_observer`: an
  optional `(direction, text)` hook the core driver invokes for every SCPI
  write/query, so the framework-layer evidence engine can trace the wire
  protocol without the core driver package depending on Robot Framework,
  logging policy, or RFDS-008 at all.
- Wrapped every public keyword with the new evidence recording (opt out with
  `evidence_enabled=${FALSE}`); added `Export Diagnostic Bundle` to zip a
  given alias's evidence for troubleshooting.
- Added `tests/hardware/verify_all_keywords.robot`: an RFDS-019 real-hardware
  conformance suite exercising all 62 public keywords against a real N83624
  over TCP, gated behind `ALLOW_OUTPUT_ON` for anything that energizes a
  channel. Two emulator-only keywords are exercised via a secondary
  in-process emulator session (RFDS-019 §11.1 approved-simulator allowance).
  Validated end-to-end (56/62 passing, 4 expected skips with
  `ALLOW_OUTPUT_ON=False`, remainder require real hardware or UDP) against a
  throwaway TCP bridge wrapping the driver's own `SimpleN83624Emulator`,
  which surfaced and fixed:
  - an alias collision between Suite Setup and the keyword's own test case;
  - `Measure Voltage Channels` requiring a list/CSV argument, not a bare int;
  - `Raw SCPI Write` desyncing the next query when used to send a
    query-shaped command (`*OPC?`) instead of a genuine write;
  - per-test full 24-channel `All N83624 Outputs Off` sweeps in setup/teardown
    made the suite unnecessarily slow — narrowed to the single channel each
    test case actually uses, keeping the full sweep at suite boundaries only.
- Added `schemas/evidence/*.schema.json`, `docs/logging-and-evidence.md`,
  `guide/EVIDENCE_AND_DIAGNOSTICS.md`, and
  `scripts/validate_evidence.{py,sh,bat,ps1}`.
- Added `tests/evidence/test_evidence.py` (19 tests) and `tests/conftest.py`.
- Cross-referenced the new suite from `guide/HARDWARE_QUALIFICATION.md` as a
  precursor to, not a replacement for, Gates H1-H8.
