# Test Harness Addendum to `SCPI_DRIVER_CORE_IMPLEMENTATION_TASK.md`

This addendum records the testing requirements established after the original implementation
task was written. It **supplements and, where more specific, supersedes Sections 40, 41, 43,
and the Quality portion of Section 48** of `SCPI_DRIVER_CORE_IMPLEMENTATION_TASK.md`.

It does not change the core architecture, framework-independence rules, transport contract, or
representative migration requirements.

## Updated Section 40 — testing requirements

The test strategy is layered. Default CI must remain independent of physical hardware and
external laboratory endpoints.

Required hardware-free layers for `scpi-driver-core` are:

```text
pytest unit/regression tests
reusable transport-contract tests
Hypothesis property tests
ScriptedScpiTransport deterministic simulation
local TCP/UDP loopback integration
PyVISA-sim integration through VisaTransport/PyVISA
pytest-timeout global bounds and explicit deadlock watchdogs
```

Real-instrument HIL tests remain a separate layer marked `hardware` and are not part of the
default CI gate.

### Property testing

Use Hypothesis where generated cases add meaningful evidence, especially for:

```text
binary block framing/truncation/size limits
SCPI text terminators and framing
numeric/bool/CSV/engineering parsers
ReadRequest bounds and field combinations
retry/backoff schedules
concrete-driver validators and value formatting
```

Keep explicit regression cases for known failures. Property tests complement rather than
replace deterministic tests.

### VISA simulation

Use PyVISA-sim to test the real software integration path:

```text
ScpiSession -> ScpiClient -> VisaTransport -> PyVISA -> PyVISA-sim
```

For a concrete VISA driver, cover identity/communication plus representative read and write
operations through the public driver API where technically feasible.

PyVISA-sim is not a replacement for `ScriptedScpiTransport` or HIL.

### Timeout and concurrency protection

Use pytest-timeout so blocked I/O, polling, worker threads, recovery, or lock regressions fail
in finite time. Repository defaults are:

```text
per-test timeout: 30 s
whole-session timeout: 600 s
```

Deadlock-specific tests should use a shorter explicit timeout.

Production timeout/deadline behavior must still be tested directly; the pytest watchdog is a
last-resort test-run bound, not application logic.

### Coverage

Target meaningful branch/statement coverage remains **>= 90%**. Coverage percentage does not
replace behavioral evidence from integration, property, concurrency, and HIL tests.

## Updated Section 41 — quality gates

CI must run equivalent checks:

```bash
ruff check .
ruff format --check .
mypy src
pytest -m "not hardware" --cov=scpi_driver_core --cov-report=term-missing
python -m build
```

The supported matrix is Python 3.10, 3.11, 3.12, and 3.13 unless the package metadata is
changed deliberately in a later version.

Hypothesis CI runs use the deterministic `ci` profile. Test-only packages remain development
dependencies and must not be imported by runtime modules.

## Updated migration rule

Every migrated concrete driver must preserve existing behavioral/HIL evidence and add a final
framework-independent test harness that reuses the core testing patterns where applicable:

```text
unit tests
ScriptedScpiTransport/mock scenarios
Hypothesis properties
PyVISA-sim for VISA paths
pytest-timeout finite bounds
separate hardware/HIL tests
```

If a layer is technically inapplicable, document why in that driver repository.

Do not create new generic abstractions solely to reduce repetitive code generated by a code
agent. Explicit driver methods are preferred when they are easier to audit. Generic extraction
requires demonstrated reuse across multiple real drivers or a concrete shared requirement such
as protocol/session behavior, validation, or tooling metadata.

## Updated quality acceptance evidence

In addition to the original Section 48 Quality checklist, acceptance now tracks:

- [x] Hypothesis property-based protocol/model coverage exists
- [x] PyVISA-sim end-to-end VISA integration exists
- [x] pytest-timeout supplies finite per-test and session bounds
- [x] explicit multithreaded deadlock/watchdog coverage exists
- [x] default CI explicitly excludes `hardware` tests
- [x] normal CI passes the full hardware-free harness across supported Python versions

These checks strengthen the generic-core evidence but **do not satisfy the representative
migration proof**. Real driver migration/HIL remains required before `v0.1.0` is tagged.

See `docs/testing.md`, `tests/README.md`, and `AGENTS.md` for the maintained operational
guidance.
